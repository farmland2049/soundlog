# Soundlog 成果页面与调试后台

## 2026-11-17：默认直接看成果

双击`启动Soundlog.command`进入成果页面。会议按时间显示主题、总结、纪要、结论与方向、待办清单和开口项；交谈和生活事件分别记录。侧栏还可直接阅读学习知识、创作提纲和跨天复盘，日期与主题支持筛选。待办归属于会议/交谈，不自动视为本人已接手的今日任务；未有依据的负责人和期限不补造。

原工作台完整保留在地址后加`debug/`的独立调试后台，可从侧栏底部进入。原文、回听、逐句时间戳、身份校准、过程状态、候选与哈希等只在后台查看。下方原工作台说明均指调试后台。

成果页源码为`workbench/product.html`、`product.css`、`product.js`，数据由`/api/products`读取。`soundlog_memory/product_view.py`发布经agent整理的不可变成果版本，绑定已交付原文事实并验证来源变化；API白名单仅返回成果字段。私有成果方案不进入Git；`soundlog_features.py products --spec 方案.json`用于手动agent管线。旧日未单独整理的内容沿用已有场景，不自动重新判定成会议。页面时段是引用材料的覆盖范围，不作为精确会议签到起止。

## 手动入口：说“开始”

在Soundlog本线程说“开始”，agent就检查`录音/待处理/`并接续已有任务，完成本机转写、原文提炼、语义筛选、每日内容、事项/知识/创作、适用的跨天复盘与未答问题，最后给成果入口。用户不逐阶段操作；页面用于查看进展与交付，取消额外的分步启动按钮。没有新音频仍会处理未完问题；成果先做到有用、有出处，不等待文案和界面完美。

## 本人声音与“我的表达”

“我的声音”集中展示少量有原文出处的短片段，支持回听后选择“是我／不是我／不确定”，并可撤销。确认仅绑定该片段的证据、原音哈希和偏移，不扩散到同号说话人、不绑定其他人姓名。样本及确认历史留在本机忽略目录`记忆库/运行/本人声音/`，不写成正式个人记忆。

“我的表达”分别显示用户确认的本人片段和模型试点候选。原句仍是机器转写；认出声音不代表转述、假设、观点或承诺已经成为真实发生、正确或完成的事情。模型候选保持未确认，不进入本人事实层。声音确认或特征提取实现改变后，旧候选自动隐藏，等待重算。

当前本人声音工作流使用独立的`voice_embedding.swift`桥接既有本机CoreML声学模型，核对固定清单的资产哈希，编译与运行均禁网，没有下载或测试语义大模型。短语音在内存中重复填充模型的固定窗口以避免补静音影响特征；不改写源录音。通用SoundlogCLI中的旧整文件身份提取器仍是骨架，不能把这个试点称为所有录音都已实现身份识别。

只读MCP和新建问答/补查材料会携带voiceAttribution：严格按证据ID、源哈希与原始起止偏移核对，self/other仅代表用户对该片段的确认。旧问答不静默重写，其他语句和整段摘要不自动继承身份。试点模型候选不混入用户确认标记。

开发命令：`soundlog_voice.py prepare/status/extract/calibrate/probe/scores`。prepare准备校准页；extract提取匿名声学特征；calibrate按原始录音文件留出，避免同一文件的模板自匹配；probe只生成额外试点候选，scores返回原始余弦相似度而非概率。校准算法在开发中选择，结果不是独立生产准确率。全部向量、音频指针和用户确认保留在本机，不进入Git。

原音回放与跨天对照已接入：在原文依据中点击“回听这一句”，核对来源后按原始偏移定位，使用播放器播放，到片段末尾暂停。底层按字节范围读取完整原文件，没有裁剪、转码或改写音频，原文件时长和进度条仍可见；定位与播放不代表听音语义校订。

每日记录或检索结果可选择最多4条内容，使用顶部“表述对照”并排阅读；知识主题包含多条素材时也提供对照入口。各条保留独立日期、摘要、原句和回放，不自动认定同一身份、事项或真实矛盾。选择临时保存在当前页面，刷新后清空，不写入正式记忆。

音频仅按已验证证据ID寻址项目已归档目录；目录越界、符号链接、原音缺失或SHA-256不符时拒绝回放并提示原因。关闭弹窗或切换详情会暂停当前播放。

## 打开方式

在项目文件夹双击`启动Soundlog.command`。入口使用现有Python环境，启动本机服务并打开浏览器；重复双击核验工作区和健康状态后复用服务，不重复启动。终端提示成功后可关闭该终端窗口。工作台独立在后台运行；电脑重启后再次双击即可。

首次启动若未找到Python，会显示错误并停下；不会安装依赖。启动失败详情在本机`记忆库/运行/自动管线/workbench.log`。无交付资料也可打开，页面显示真实空状态。入口不执行语义模型或外部日历动作。

命令行等价入口：

```bash
python3 scripts/launch_soundlog.py
python3 scripts/launch_soundlog.py --no-open
```

直接运行服务可在终端按Ctrl+C停止：`python3 scripts/soundlog_hub.py --reuse-session`。更改后端代码时需重启服务，普通刷新会重新读取静态界面资源。入口文件位于根目录是为方便Finder双击；界面源码和设计说明收在本目录。

## 界面与信息架构

视觉采用暖灰底色、低饱和绿色主色与米色儿童学习标识；侧栏固定导航，顶部统一检索，正文卡片按内容任务组织。避免在产品主流程展示运行目录、哈希和内部编号。全部样式、脚本与图形本机提供，不使用CDN、外部字体或新前端依赖。

|栏目|交互与可用产物|
|---|---|
|概览|真实资料计数、最近交付、栏目分布、六阶段状态；进入最近一天或检查新录音|
|每日记录|日期选择、用途筛选、当天搜索、时间线、结构化场景；展开摘要及原句、文件和偏移，内嵌回查全文|
|事项线索|文字筛选、关联/冲突/当时承诺/原话称完成筛选；展开证据时间线和关联理由，保留现时状态未知|
|证据问答|输入问题及可选检索提示；保留等待、处理中、失败和回答状态；回答可展开引文，十秒检查队列更新|
|知识花园|成人/儿童独立主题图、筛选卡片、可点击节点；概念、方法、问题、新增联想和完整卡片原文|
|创作素材|写作提纲、规整对照、重点标记、请求草稿分栏；产物在工作台内预览，草稿可查看原始依据|
|跨天复盘|范围、资料天数、主题和缺失日期；新交付或来源变化标记待更新；打开完整复盘与引用|
|处理与连接|当前阶段、待处理文件、检查与本机处理入口；只读连接能力说明、实际日历记录及片段确认数量|

统一搜索支持整理内容与完整原文，空格分隔关键词按AND匹配。检索未命中不表示从未提过。文件预览以本机沙箱iframe呈现，Markdown原文仍可独立阅读。键盘支持Tab、Enter、Escape及Cmd/Ctrl+K检索；状态不只靠颜色区分。CSS为窄屏提供折叠菜单和单列布局，实际浏览器验证范围以测试记录为准。

## 数据与执行边界

### 我的事项

侧栏“我的事项”按逐项审阅内容展示“我的承诺”“别人交办我的事”“我的想法与表达”，支持展开精确原文、来源时间和原音回听。声音已确认仍需语义判断，只有相似声音不会进入这里；不适合生成的片段可记录理由后略过，交办不明确时允许为空。

`python3 scripts/soundlog_features.py personal --spec 记忆库/运行/产品功能/personal-spec.json` 发布经agent审阅的个人内容。方案字段与连续回应要求见`scripts/pipeline-agent.md`；JSON、Markdown与哈希回执保存在`产出/自动交付/personal/`。历史版本不可变，标签撤销会使页面隐藏相应个人内容，不能继续用旧导出冒充当前归属。录音里的承诺尚不代表今天未完成，不自动生成日历或对外发送。

`GET /api/personal` 返回有效项、略过项与确认改变后隐藏项；只读MCP的`soundlog_task`增加`personalContext`，用于区分普通匿名事项与经审阅的个人内容。首版只覆盖当前5段用户确认声音，不代表整库已完成个人化整理。

`scripts/soundlog_memory/workbench_view.py`将已交付工件转换为界面数据，读取时核对不可变来源哈希；不生成新事实或修改原始机器稿。真实数据缺失时显示空状态，不塞演示统计。来源和现时状态仍保留未知。

成果页在转写后启动一次本机 Codex CLI，继续整理和发布。用户也可在对话中按 Soundlog skill 手动接手。

只读MCP接入、正式记忆写入、身份登记和外部事件执行仍有各自配置与授权流程；页面仅呈现已有记录，不提供绕过授权的快捷按钮。服务只监听127.0.0.1，私有随机路径、Host/Origin校验和CSP继续有效；不上传音频、转写或截图。

## Soundlog 应用入口与处理按钮（2026-11-17）

打开`界面/应用/Soundlog.app`，可将该图标拖入Dock。应用使用原生macOS独立窗口展示本机成果，不弹终端；重复打开激活已有窗口，关闭窗口后从Dock可重新唤起。服务缺失时启动，正常时复用。应用必须留在当前项目路径下，不要只移动.app到其他目录；Dock保存的是入口引用。源码`界面/应用/Soundlog.swift`，用已安装Xcode工具运行`python3 界面/应用/build_app.py`重建；编译产物被Git忽略。

成果页右上角“开始处理录音”左侧显示整条管线的六阶段进度：检查来源、本机音频分析、语义提炼、逐项筛选与日交付、派生成果与复盘、发布校验。进度由当前管线状态驱动，属于阶段估算，不伪报逐文件百分比；失败或等待状态会停留在对应阶段。按钮运行时禁用重复点击，无任务时显示等待开始，完成后显示已核验。未增加后台模型服务、调度、外部上传或依赖安装。

## 录音来源设置与前置导入（2026-11-17）

成果页右上角“设置”可开关当天语音备忘录导入、添加多个外部目录，每行一个完整路径。设置保存到本机忽略目录`记忆库/运行/自动管线/audio-sources.json`，不进入Git；磁盘无需当前连接，连接后再点击开始即可。目录递归扫描子目录，不跟随符号链接；不能选Soundlog项目目录或包含项目的上级目录，避免回收自身产物。

点击“开始处理录音”先并行扫描语音备忘录与已配置目录，随后串行复制，全部导入动作结束后接原`Pipeline.start()`。权限不足、目录缺失、数据库不可用等情况跳过，不阻塞其他来源和既有收件箱。CLI/Skill原`start`不额外扫描其他来源，按钮是前置导入入口。

语音备忘录只读本机`CloudRecordings.db`当天元数据与已下载文件，Apple纪元转换按上海日期筛选，录制时间须与文件名一致；不读波形或改数据库，不触发iCloud下载。外部目录不限制录制日期，支持14位时间戳或`YYYYMMDD HHMMSS`等日期时间开头的名称，输出14位录制时间加原扩展名，不使用修改时间猜录制时间。无法确认时间的音频跳过，不为导入而造时间。

原件不移动、不重编码；源文件至少稳定60秒且非空，复制期间变化则不发布；隐藏临时文件完整复制后以独占方式放入收件箱，保留原修改时间。导入账本按内容哈希去重（跨已配置来源、收件箱及已归档的既有导入），同名内容不同则保留源文件并跳过，不覆盖、不改秒数。手动导入到不同名字的旧文件不承诺全盘哈希查重。导入回执与来源路径只保存在本机，后台“处理与连接”可查看具体跳过理由；成果页只保留简短运行状态，设置中有最近导入数量。

语义整理依赖本机已登录的 Codex CLI，并遵循 Soundlog 的发布流程。

## 处理历史（2026-11-17）

侧栏底部按文件显示录音时间、文件名、音频处理状态和内容是否发布；已发布可打开当日成果。未发布不等于未处理，静音等文件可以没有语义成果。无状态的归档文件只标已归档。等待agent时不把转写成功称为全流程完成。

M4A按明确容器优先解析时长，避免压缩字节中的偶然MP3帧头干扰。覆盖缺口保留在清单，不因空白或编码补齐等非满覆盖阻断归档；真实范围越界仍拒绝。

### 自动续跑与手动接手

点击“开始处理录音”，Soundlog 在发现待整理、待筛选、待发布或待答问题时，自动用本机 Codex CLI 和 `$soundlog` skill 继续处理。本轮成果通过 Soundlog 原有管线发布，页面随后刷新。页面根据队列状态和成果回执判断是否完成。

后台整理未完成时可用同一按钮重试，也可点“复制提示词（备用）”交给能访问本机项目的 Agent。详细信息保存在私有运行目录中的 `agent-cli.log` 和 `manual-run.json`。
