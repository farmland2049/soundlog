# soundlog 三类录音识别执行计划

制定日期：2026-11-09。状态：实施中；第一阶段时间轴核心、输出格式与合成单元测试已完成，真实录音人工基线待确认。实施时逐任务完成需求符合性与代码质量检查；未经明确授权不提交或推送。

**目标**：任意指定录音生成逐字稿及绝对时间戳，独立输出环境声音候选和说话人时间线，覆盖本人自言自语、对谈和多人录音。

**架构**：保留原件；苹果Speech负责文字和相对时间，SoundAnalysis负责声音候选，FluidAudio离线管线负责匿名说话人及声纹，普通程序完成原时间轴对齐。本人身份由用户确认样本后匹配；场景自动推理不在首期。

**技术主线**：已有Swift原生工具及FFmpeg；拟以Swift Package Manager接入FluidAudio离线说话人组件。具体公开接口和依赖开关在实施时读取固定版本源码，不假定此处拟定的代码文件或API已经存在。

## 1. 固定输入、数据结构与测试基线

**拟新增**：`资料/输出格式.md`、`测试/样本清单.json`、`Tests/SoundlogTests/FilenameTimeTests.swift`、`Tests/SoundlogTests/TimelineTests.swift`。

步骤：
1. 记录输入文件路径、原字节哈希、时长、文件名时间解析结果、引擎和参数版本，不更改原件。
2. 定义相对秒数和绝对钟表时间；文件名无时区时不伪造时区。不合法名称报错，不用修改时间替代。分块必须记录原文件偏移。
3. 确定文字片段、声音分类窗口/合并事件、说话人片段、身份匹配及处理清单的字段；保留来源和未知状态，缺少原生置信度时不编造数值。
4. 先写失败测试：有效/无效时间名称、跨日、原始偏移、空白、没有文字但有人声、时间区间合法及不倒退。
5. 从现有原录音选代表片段，保存原文件与偏移映射。本人/参与人及真实环境以用户确认或明确人工核验为准；未核验不算真值。

**验收**：时间映射与字段测试通过；原件哈希未变；测试真值与模型输出分开保存。

**当前结果（2026-11-09）**：Swift时间轴核心和输出格式已实现，7项单元测试通过；五份原录音SHA-256与迁移清单一致。公开样本清单仅含合成用例，真实录音的人工真值仍待确认。

## 2. 建立通用苹果转写入口

**拟新增**：`Package.swift`、`Sources/SoundlogCLI/`、`Sources/SoundlogCore/`及`Tests/SoundlogTests/TranscriptionTests.swift`；具体类名实施时按已读源码确定。

**参考而非直接覆盖**：`工具/native_transcribe.swift`、`工具/native_batch.py`。

步骤：
1. 新入口接受单文件或文件夹，不再固定历史三个文件，也不依赖`.hermes/attachments`绝对路径。
2. 复用已验证的SpeechAnalyzer/SpeechTranscriber接口，保存原始相对时间及用户可读的绝对时间稿。
3. 区分“已处理音频覆盖”“识别到文字的范围”“文字是否准确”；不能把无字区间当作未消费，也不能用空结果伪造识别成功。
4. 进度按实际产物原子落盘；续跑必须核对源哈希、引擎及参数，不能仅看文件名存在。原始结果与渲染分离。
5. 先测试短片段和尾段，再测试单文件；历史稿件保持不变，新运行写独立运行目录。

**验收**：任意合法文件可进入管线；绝对时间正确、空白不压缩；同输入同参数可复用，失败可恢复；异常、空输出有明确状态。

## 3. 扩展整文件环境声事件提取

**拟新增**：`Sources/SoundlogCore/`下声音分析模块、`Tests/SoundlogTests/SoundEventTests.swift`。

步骤：
1. 按本机SDK读取SoundAnalysis接口，列出实际支持类别，不把此前303类硬编码为永远不变。
2. 独立遍历整份录音，不只分析文字识别命中区间；保留分类窗、多个候选及原生置信度。
3. 对连续同类候选合并事件，阈值、最短时长及间隔写成可追踪参数；原始窗不删除。不能把分类窗边界当精确真实起止。
4. 测试无文字的环境声音、持续声、间歇声、多种声音重叠和未知候选；输出供后续推理，不自动确认地点或外放来源。

**验收**：窗口时间能映射回原录音；事件可回查候选；人工抽查误报与漏报；低分不硬分类。

## 4. 接入FluidAudio离线说话人管线

**拟修改**：`Package.swift`；拟新增`模型/`、`记录/模型安装清单.json`及`Tests/SoundlogTests/SpeakerTimelineTests.swift`。这些目录本轮不预先创建。

步骤：
1. 读取FluidAudio选定版本的Package.swift、离线加载器及下载选择逻辑；固定实际源码版本和依赖锁定信息，不使用未核实的版本号。
2. 当前元数据基线为`FluidInference/speaker-diarization-coreml@df2625ac79a7ac6b65ad868fee6d80f320da4232`；授权后下载Segmentation、Embedding、FBank、PldaRho及plda-parameters.json，核对必需文件、哈希和许可。
3. 元数据合计21,599,417字节（21.599 MB），不含SDK、依赖及编译缓存，不是运行内存。只下载所需固定版本，不拉整个混合模型仓库，不顺带安装ASR/TTS或恢复Whisper。
4. 代码Apache-2.0，上述指定模型在CC-BY-4.0范围；当前转换仓库gated=false。保留NOTICE与署名来源，不笼统推及其他模型。运行不依赖付费云端API。
5. 先构建和加载验证，再跑单人、双人和重叠片段；输出匿名说话人及原始起止，不强制至少两个人，也不靠文字判断身份。
6. 按原时间轴与文字对齐，明确一段跨人及重叠的处理；无字人声保留。若必须分块，验证块间同人关联，禁止简单拼接块内编号。

**验收**：实际本地模型加载成功、匿名时间线可用、编号混淆有记录；下载失败或质量不足即报告，不以脚本成功退出代替验收。

## 5. 本人样本确认及跨文件匹配

**拟新增**：本地`身份库/`、可回听的样本引用与身份纠错接口，`Tests/SoundlogTests/IdentityMatchTests.swift`。

步骤：
1. 提供原文件/时间范围供用户确认本人声音，未经确认不绑定姓名。不自动采集无关人员身份。
2. 复用声纹模型提取已确认样本，保留登记依据、模型版本及变更记录；本人声纹单独按私人数据保护。
3. 使用确认样本校准匹配与拒绝条件，支持“未知”，不能把相似度直接当校准后的身份概率。
4. 测试同人不同文件、远近变化、噪声、他人及外放；支持拆分、合并、改名和撤销误认。

**验收**：用户确认的本人样本能被回查；跨文件标签不依赖Speaker 0；误识别可拒绝及纠正。未确认或不可靠的片段继续匿名。

## 6. 统一结果及完整长录音验收

**拟新增**：`产出/运行批次/<运行标识>/`、`记录/性能与质量验收/`及端到端测试；运行标识与路径格式在步骤1确定。

步骤：
1. 同一运行输出带说话人标签的TXT/Markdown逐字稿、环境事件JSON、说话人时间线JSON、身份引用及处理清单，三类结果共享时间轴，允许各模块独立失败和续跑。
2. 在同一代表集人工标注后核对：文字错漏、事件误报漏报、同人拆分/异人合并、重叠归属、本人误认。没有真值不报准确率。
3. 运行完整长录音，测包含加载与落盘的完整墙钟耗时、峰值内存及冷/热启动边界；不得外推社区M5基准或承诺预定速度。

5. 检查代码、测试、真实产物及隐私边界，按证据更新PROJECT_STATUS.md；保留原件和最终稿，清理已不需要的临时物，不擅自删除验收证据。

**验收**：在真实运行、完整覆盖和人工抽查均有证据后，分别说明已通过与未通过；不能用字数、退出码或无报错宣称质量合格。若质量不足，记录问题并由用户决定继续调整或换路线，不自动安装所有候选。
