# 录音产品功能落地路线与交付规格

日期：2026-11-15；实施更新：2026-11-16。本文保留原始范围与完成条件；实际功能、产物、验证及保留缺口见[A—F功能使用与验收](A-F功能使用与验收.md)，不能仅凭本文规划断言实现。

## 1. 目标和当前基线

目标是将普通录音笔记录转为能阅读、能提问、能跟进、能复用的个人资料。以用户提供的 PLAUD、极米、讯飞、Looki、千问 Note、GetSeed 功能清单作为需求参考，本文不重新验证厂商宣传。

当前已实现本机转写/声音事件/匿名分人、原始时间轴场景素材、四类语义提炼与筛选入口、儿童/成人学习分栏、Markdown与HTML原文回查、跨已交付日期关键词检索、可恢复任务状态。自动化通过本线程每天08:00（上海时间）检查，需电脑和Codex可运行。语义由agent实际阅读完成，脚本负责确定性校验和交付；不能将这一组合称为全链路断网自治系统。

现有八天交付采用摘要初筛结果；不能把引用一致性检查视为逐句语义验收。管线已有合成数据测试，仍需在下一批真实新音频上验证ASR至最终交付全链。

高价值内容由目标功能的用途决定。有明确主题、信息或上下文的内容可以保留；无法理解的片段暂缓，原文继续可查。说话人未确认不妨碍匿名记录；不能把来源不明的节目、英语测评回答或他人经历变为本人事实。儿童学习与成人学习独立组织。用户无需逐条确认，重要身份、实际冲突及外部执行才处理必要授权。

## 2. 总体数据路径

```text
录音/待处理
  → 输入稳定和重复检测
  → 本机ASR、声音事件、匿名说话人
  → 保持原始时间轴的证据快照
  → agent逐块阅读、场景与功能提炼
  → agent逐候选判断用途及引文支持，保留或暂缓
  → 统一内容记录与版本历史
     ├─ 当天：时间日记、场景纪要、学习笔记、重点
     ├─ 跨天：事项变化、项目脉络、知识关联
     ├─ 查询：原文检索、自然语言问答和来源
     └─ 派生：脑图、信息卡、规整稿、写作素材
  → 校验及原子发布 → 本地工作台与文件交付
```

内容记录至少带：稳定ID、来源快照与录音哈希、证据ID、原始偏移、录音时间、事件时间原话、来源类型/未知、匿名说话人线索、功能用途、陈述性质、当前审核层级、版本和变更依据。不能用录音时间替代话语中提及的事件发生时间。

新增产品模块必须消费这一层证据；不各自重新转写或自行拼接人物身份。脚本校验引用、覆盖与哈希，agent判断语义；分别记录两种结果。

## 3. 交付入口和文件约定

继续沿用 `产出/自动交付/`，不另建互相竞争的资料库。不可变批次保留，目录清单按日期引用最新完整批次。

| 用户入口 | 用途 | 建议交付形式 |
|---|---|---|
| 本地工作台 | 日期浏览、状态、搜索、问答、主题、事项 | `index.html`，交互问答阶段升级本机服务；Markdown继续独立可读 |
| 每日首页 | 一天发生/讨论/安排的概览 | `YYYY-MM-DD/README.md`，链接该日全部产物 |
| 时间日记 | 按录到的时间段回顾，而非推测完整行程 | `timeline.md` + `timeline.json` |
| 每日复盘 | 重要事件、结论、变化、未决问题 | `daily-review.md` |
| 场景纪要 | 不同用途的结构化摘要 | `scenes/<id>.md` + `scenes.json` |
| 历史事项与跟进 | 承诺、要求、提议、完成/取消的依据 | `actions.md` + 跨天 `tasks.json` / `task-history.jsonl` |
| 儿童学习 | 主题、练习、辅导方式、遇到的问题 | `child-learning.md` + 结构化学习片段 |
| 成人学习 | 概念、方法、案例、问题及来源 | `adult-learning.md` + `knowledge/<id>.md` |
| 问答 | 回答、引用、未知和冲突 | 工作台会话；按需保存 `answers/<id>.md` / `.json` |
| 可视化 | 主题脉络、要点和待办概览 | Mermaid `.mmd` + `.md`，HTML可视化；SVG后续按需导出 |
| 规整稿 | 更易读但可与原文对照 | `clean/<id>.md` + `corrections.json` |
| 重点与派活草稿 | MARK邻近原文、明确语音请求 | `highlights.md` + `intent-drafts.json` |
| 运行和证据 | 查看进展、失败和来源 | 沿用来源索引、`screening.json`、`receipt.json`及本机状态 |

文件名为目标规格，新增文件须在对应阶段实现后才进入交付清单。当前已交付的 `journal.md` 等文件保留兼容；升级后添加说明和重定向入口，不机械改写历史包。

## 4. 实施顺序与完成条件

### 阶段A：把当天结果做成完整的阅读产品

优先级第一。沿用现有管线，增加统一场景记录及每日汇总器。先完成真实新批次全链检查，再扩展展示。

- 时间日记：按原始顺序列时间段、主题、发生/讨论/计划、来源。保留无文字或空白区间，不用它们推断活动。跨文件接续结合时间和语义，不按固定间隔强行合并。
- 场景模板先做四种：工作/技术讨论（背景、问题、依据、意见/分歧、结论/未决）、生活交流（具体内容、安排、结果线索）、儿童辅导（主题、方法、练习与问题）、成人课程/播客/学习（概念、方法、例子、来源）。不是每段对话都叫会议。
- 每日复盘在当天内容上做第二次归纳，最多突出几个重要主题，不逐条重复候选。没有材料支撑的栏目可以为空。
- 页面提供“当天概览—主题—候选—原文—录音偏移”逐层展开，并把学习场景分栏。

产物：每日首页、时间日记、场景纪要、每日复盘及更新工作台。实现点：新建日汇总/模板模块，接入 `Pipeline.publish`，保留现有五类文件。

完成条件：有文字、无文字、跨午夜、外放混合和全暂缓样本均能正确交付；新增真实批次完整走通；所有展示条目有可打开的来源，未完整处理的日期不替换旧交付。用户已反馈的混合音源、找人后交谈、儿童/成人区分须回归检查。

### 阶段B：跨天事项跟踪

依赖A的场景与统一记录。先建设“事项线索账本”，保留主体未知及关联待定，不伪造负责人或完成状态。

- 区分请求、承诺、建议、条件、原话称完成、取消、改期。记录当时的事件时间和期限原话。
- 稳定事项ID与来源断言分开：多个相似句可以提出关联，但关联本身要保存依据和置信边界。
- 相同关键词或相邻时间不能自动合并；对象、行为、主体和时间足够一致才能提出跨天关联。
- 显示“当时承诺 / 后续称完成 / 暂无后续证据”等状态。不以缺少新录音判定仍未完成。
- 相对日期仅在事件锚点明确时解析，并保留原话和解析依据；不确定时不落日历。

产物：事项总览、每日变化、每项证据时间线、`tasks.json`与追加式变化记录。实现点：事项聚合/变化模块，工作台事项页；先只读。

完成条件：建议不变承诺、否定不变执行、已完成不再列成明确未完成；同名不同事不合并；跨录音冲突可并列呈现。用用户已确认的“答应发送项目资料”等作为范围受限回归案例，不能扩展声音身份。

### 阶段C：带证据的 Ask AI

可与B并行，在A完成后投入使用。先做无需向量模型的检索问答：agent提炼查询条件和同义表达 → 关键词/日期/主题/原文检索 → 读取邻近原文 → 回答。不能只查592条筛选保留项，原始转写也应成为检索通道。

- 第一入口是当前助手：用户问一句即可检索本机资料并回答；第二入口才是工作台问答框。
- 第一版支持“讨论过什么”“当时答应了什么”“某天发生/提到什么”“前后说法有什么变化”，时间范围明确展示。
- 回答格式：结论、原文证据、时间和文件、未知或矛盾之处。对照问题需逐一覆盖相关时期，记录实际检索范围。
- 历史录音能证明有人说过，不自动证明当前事实；无证据应答未知。检索不到不等于从未说过。
- 浏览器不能自行使用当前agent登录能力。页面问答通过持久化问题队列，由本线程自动化处理并返回结果；明确显示等待/处理中/完成/失败。即时后端模型接入另作具体选择，不假装静态HTML已能实时问答。

产物：检索服务/工具入口、问答队列、工作台回答卡及可选Markdown/JSON导出。实现点：复用 unified_search，加查询计划、证据读取、回答验证与问答任务状态。

完成条件：冻结一组跨天、同义、否定、无答案、冲突和媒体归属案例；回答引用均存在，实际结论需由对照原文评分；报告检索召回、回答支持性和无依据回答，不用引用哈希或同一agent自评冒充独立准确率。

### 阶段D：知识卡、脑图与信息卡

依赖A，部分利用C检索关联。将成人、儿童材料分开组织，外部观点与个人表达有单独来源属性。

- 知识卡：概念/方法、例子、原话依据、仍不明的问题。对录到的医疗、营养、技术观点标为谈话观点；若另行查证，则外部核验结果另存，避免覆盖原话。
- 跨天关联：同一主题的补充、相反看法、未决问题和新例子；相似不等于同一事实。
- 脑图只表达已支持的主题层级和关系；纯分类关系与因果关系分别标明，不能从关键词共现推导因果。
- 信息卡呈现一次讨论的重点、结论和事项，优先可编辑HTML，不依赖生成式图片。
- 笔记发芽：明确分开“录音里已有的内容”和“agent新增联想/问题”，新增部分带生成标记。

产物：知识卡Markdown/JSON、主题索引、Mermaid脑图及HTML信息卡。实现点：知识关联模块、图形派生器；可视化失败不影响日记与原文交付。

完成条件：卡片和图节点可以回到证据；成人内容不混入儿童学习记录；新增联想不写成历史发生或原话。

### 阶段E：规整稿、MARK与创作素材

依赖A/C。先提升复用体验，再做外部执行。

- 规整稿独立生成，保留原稿、段落引用和差异；不得删除否定、条件、推测或改动金额。专名不清时标疑问及候选，确有上下文或用户更正才建议纠正。
- MARK识别“标记一下”“这个记住”等明确表达及相邻语境；只是录音中的引用、播客口令或别人的请求时不得当作本人指令。
- “帮我写/整理/发……”生成请求草稿：区分希望生成的内容和对外发送意图。录音历史请求不直接授权执行。
- 写作素材先做报告提纲、发言提纲和文章素材包，来源可追溯。小红书卡片、公众号排版和可编辑PPT作为按需导出模板，不为每段录音批量生成。

产物：对照规整稿、纠错建议、重点摘录、请求草稿、带来源的写作提纲。

完成条件：口令嵌在媒体引用里不会自动派活；规整稿语义保持；创作新增内容有标记，外部发送停在具体可审阅稿件。

### 阶段F：跨助手记忆与经授权的行动

依赖B/C及版本机制。读取接口可先行，正式记忆新增写入和外部动作按实际授权落实。

- 统一只读接口：查询某日、搜索原文、读事项及来源、读取主题背景。输出明确的记录时间、状态和未知项。
- Basic Memory保留 source/candidate/confirmed 的边界，支持更正、去重、撤销与逐篇读回。现有两日试点可作为验证样本，不能自动扩大写入范围。
- 人物身份单独建确认与解绑流程，不能把一个片段确认传播到所有同号说话人。
- 日历、提醒、任务应用仅在对象、时间、意图清楚且获得具体授权后执行，保存目标应用回执和幂等键。执行失败不显示成功。

产物：助手可读的接口说明与查询工具、记忆同步差异/回执、日历或任务执行草稿及真实回执。

完成条件：不同助手拿到同一份有来源的背景；更正后旧状态不再被当当前状态；重复重试不重复创建任务，撤销有证据。

## 5. 需要额外输入或条件的扩展

| 能力 | 所需输入或条件 | 路径 |
|---|---|---|
| 照片/PPT/板书融合 | 用户提供图像/课件及时间锚点 | 独立图文对齐与图片来源记录，产出学习纪要；无图不补画面 |
| 生活Vlog/漫画 | 授权的视频或图片素材 | 有素材后建设剪辑/画面派生流程；录音先支持有出处的故事提纲 |
| 多语种翻译 | 可靠外语转写、术语上下文 | agent翻译与原文并列；新语种识别单独实测，不能复制厂商覆盖数字 |
| 实时转写/同传 | 流式音频和低延迟处理 | 独立技术验证，不阻塞录音结束后批处理 |
| VCS、远距定向降噪 | 相应硬件与原始声道 | 不以文本后处理假装补齐拾音能力 |
| 全链路本地语义模型 | 用户改变当前暂停要求后再评估 | 当前继续使用agent能力，不安装/下载/测试本地语义模型 |

## 6. 开发与测试节奏

按“可用功能包”推进，不承诺没有依据的固定工期：

1. A先交付日首页、时间日记和模板；下一批真实录音验证自动处理后，才报告全链真实跑通。
2. B和C建立事项账本及基于证据的助手问答；先能读和问，再扩展界面交互。
3. D增加知识关联和可视化，让已有内容反复可用。
4. E完善重点、规整和写作素材，F逐步打通受控外部接口。

每个功能包必须有：可打开的实际产物、输入/输出绑定的回执、异常与中断用例、几项真实内容核对以及准确的能力说明。需要独立语义验收的项目继续记录缺口，不让它阻塞普通内容整理，也不把缺口冒充已通过。

现有八天结果和两批用户反馈作为回归材料；新音频验证增量处理。普通语义取舍由agent完成，无法可靠判断的内容暂缓；只有确实需要用户决策的少数问题集中提出，不反复以批次为单位索要确认。
