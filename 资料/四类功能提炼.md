# 日记、纪要、待办与学习笔记提炼

实现日期：2026-11-13。当前为本地证据导出、助手语义处理、校验导入和派生文稿流程。程序本身不调用模型、不联网、不安装依赖，也不向独立记忆库或正式Basic Memory写入条目。本地模型自动提炼尚未实现。

## 导出

```bash
python3 scripts/products.py export --date 2026-11-07 --date 2026-11-08
```

默认从新版完整场景快照读取，保存到 `产出/功能提炼/requests/prodreq-.../`。不指定日期时导出全部有文字证据的日期。

- `materials.json`：按块的逐句机器文字及文件范围匿名标签，不含本机原始绝对路径；文字仍属私人材料。
- `instructions.md`：功能用途、原文引证和未知边界要求。
- `result-template.json`：待填写结果外壳；空facts且空coverage的模板不能通过导入。
- `request.json`：本地不可变请求，记录来源快照、范围、提示词指纹和完整块材料；不需要分享。

程序不自动发送导出材料。使用已有助手通道时填写结果；每个块需有实际处理的引用或不提炼原因。

局部试验可传 `--selection selections.json`，其中为 `{selections:[{key,date,focusFunctions:[...],evidenceIds:[...]}]}`。它与 `--date` 互斥，结果明确标注局部范围，不冒充全天完成。

## 结果格式

```json
{
  "schemaVersion": 1,
  "requestId": "prodreq-从模板复制",
  "processor": "实际处理者",
  "results": [{
    "key": "从模板复制",
    "facts": [{
      "summary": "匿名发言提出明天充电，是否完成未知。",
      "functionUses": ["journal", "actions"],
      "assertion": "explicit",
      "subject": null,
      "sourceMedium": "unknown",
      "eventTimeText": null,
      "dueText": "明天",
      "taskState": "commitment",
      "evidence": [{"id": "ev-从材料复制", "quote": "我明天拿回来充电"}]
    }],
    "coverage": [{"id": "ev-从材料复制", "disposition": "used", "reason": "引用明确的充电承诺"}]
  }]
}
```

- `functionUses`：journal（日记）、minutes（纪要）、actions（待办/安排）、learning（学习/灵感），同一条可以多选。
- `assertion`：explicit、reported、suggestion、question、negated、uncertain、hypothetical，分别保留明确原话、自述/转述、建议、疑问、否定、不确定和假设。
- `taskState`：含actions时必须为question、proposal、request、commitment、reported_completed、reported_cancelled、reported_rescheduled或unknown；其他栏目为null。这是当时原话的性质，不是当前任务状态。
- `subject`：未知为null；其他值须有引文或文件范围标签依据。匿名“我”也不等于录音持有人。
- `sourceMedium`：本版只能unknown，不能自动认定现场或媒体外放。
- `eventTimeText`与`dueText`只允许期限或事件时间原话，不生成推测的日历日期。录音时间由证据派生，不当作事件时间。
- `coverage`：块内每个不同证据ID都要有used/context/unclear/no_function_content及原因。used与实际引用一致；其余原文仍在完整证据库中，不删除。

结构验证可检查逐字引文、块范围、覆盖及字段关系，不能自动证明摘要语义完全忠实。例如处理者错误地给疑问贴explicit标签，仍需语义复核发现；不能把格式通过当成质量通过。

## 导入与阅读

```bash
python3 scripts/products.py import --file /absolute/path/result.json
```

结果存到 `产出/功能提炼/results/product-.../`，包含：

- 入口 `README.md` 及每个日期的journal/minutes/actions/learning文稿。
- `facts.json`：有原话证据、匿名来源和candidate状态的功能条目。
- `coverage.json`：每块逐句处理说明、缺失块列表。
- `input.json`、`receipt.json`：输入、来源范围、处理者、实现/提示词指纹与输出文件哈希。

全部先校验再原子发布。未知/重复块、伪造引文、无依据主体、超范围日期、虚假used覆盖等会拒绝导入。缺少块时保存partial结果并返回1；只有完整请求才建立该请求自己的完成引用，没有会被局部样本覆盖的全局“全天完成”指针。错误返回2。

原样重复导入校验后复用；已发布文件发生变化时拒绝覆盖。修改后的结果保留为新版本，不覆盖旧版。分批工作时保留已完成块，合并成累计results再次导入以消除missingChunks；当前不自动把不同输入文件的块合并，以免静默覆盖人工修订。

## 与已有原子记忆兼容

原记忆协议增加可选 `functionUses`，取值与上述四类一致。无此字段的旧候选仍可校验；标签不改变原子记忆ID，精确重复合并时取功能标签并集。新导出提示词版本为 `soundlog-memory-v2-functions`，旧请求仍可按各自快照导入。

这只是协议兼容，不会因生成四类文稿就自动增加或确认原子记忆。现有137条未确认候选本轮保持原状。

## 连续时段与跨块上下文（v1.1）

可将时段保存为 `ranges.json`：

```json
{"timeRanges":[{"from":"2026-11-07T17:14:00","until":"2026-11-07T17:58:00"}]}
```

```bash
python3 scripts/products.py export --ranges /absolute/path/ranges.json
```

时段采用无时区钟表时间和区间重叠选择，不剪短跨边界的原话；不能与日期或选段模式混用。任一指定时段没有文字证据时明确报错，不静默标为完成。输出明确标为局部范围，记录起止，不当作全天日记。

每块默认附最多前后各2条、相隔不超过90秒的邻近参考，`--context-count`可设0—5；上下文另受大小限制，未附条目记录在omittedContextIds。核心utterances与contextUtterances分开：邻近内容可被引用，但每条事实须锚定至少一条本块证据，邻近参考不能计入本块已处理覆盖；引用中明确标contextOnly，文稿也区分本块证据和邻近参考。

分批结果可以安全合并：

```bash
python3 scripts/products.py combine --files /absolute/path/a.json /absolute/path/b.json --output /absolute/path/combined.json
python3 scripts/products.py import --file /absolute/path/combined.json
```

合并前验证全部块；必须同一请求，完全相同的重复块可复用，同一块的不同修订明确报冲突，不以“后文件覆盖前文件”处理。保留独立合并回执及来源指纹。合并输出已有不同内容时拒绝覆盖。

功能结果回执增加完整/已处理核心证据条数、输入事实数、精确去重数及上下文引用数。精确重复事实按摘要、状态与引用等身份合并用途；不同语义或不同证据不会自动合并。连续话题的后续细化、备选及数量口径，仍需语义复核，不能一律当作旧事实被更新。

本轮连续试验覆盖两个时段共60分钟、281条核心原话、12块：38条输入事实去除1条精确重复后为37条功能候选。与原候选引文重叠的11条另有复核建议，3条仅拟收紧措辞，尚未写回。不是两天全天处理完成。

## 查询进度与本地模型试验

`python3 scripts/products.py status --request prodreq-...` 只读核对实际导入块、核心原文覆盖及剩余块。材料导出、本地未导入草稿、邻近参考和其他范围的试验不会冒充已完成；历史修订存在差异会单列，完整完成引用还会核对文件哈希。

## 逐句审阅辅助与主题阅读版（2026-11-13）

`scripts/product_workbench.py` 不调用模型，只替审阅者处理材料与引用：

```bash
python3 scripts/product_workbench.py prepare --request prodreq-已有请求 --count 10 --completed /absolute/path/reviewed.json --output /absolute/path/packet.json
python3 scripts/product_workbench.py compile --decisions /absolute/path/decisions.json --output /absolute/path/result.json
```

prepare按请求顺序取尚未出现在指定已审结果中的块，保留完整原句和邻近参考，不预填已处理状态。completed指向明确选择的结果版本，不把历史分歧默认为已解决。编译输入为`{requestId,processor,blocks}`；每块含key、facts、coverage。facts用rows数组引用从0开始的核心行，contextRows可选；summary、functionUses、assertion和待办性质由审阅者填写。coverage为`{rows,disposition,reason}`分组，必须显式覆盖全部核心证据，不自动把剩余行标为已读。引用从不可变请求填回原句，仍需原有结构校验；compile不执行导入。输出已有时拒绝覆盖。

审读完成后按原combine/import路径合并与导入。发现旧块语义问题时另存修订，保留旧输入；历史修订分歧单列，当前采用版本须有明确选择回执，不能简单把不同版本混合。

```bash
python3 scripts/products.py reading --outline /absolute/path/outline.json
```

主题纲要为`{schemaVersion:1,resultId,reviewer,sections}`，section含date、function、title、summary、factIds。阅读版验证来源产物哈希、事实存在、日期与功能范围、同功能下重复分配；生成每个日期四类Markdown及入口，保留其余候选的展开列表并链接完整证据明细。无事实的日期仍有四类空栏目。新版本写入独立目录，重复生成先核对哈希，不覆盖被改写文件。

主题摘要由审阅者撰写，程序不宣称自动语义验收。引用、覆盖和哈希通过不能证明真实录音准确；未听音、未经独立盲评的结果仍标为机器稿语义候选。全部真实材料、纲要、候选和阅读版保留在忽略的产出目录，不写入正式Basic Memory或自动创建提醒。

## 与原子候选做只读差异对照

```bash
python3 scripts/products.py compare --result product-已有结果 --memory-root /absolute/path/memory --reviews /absolute/path/reviews.json --output /absolute/path/comparison.json
```

compare先核验结果工件哈希，再读取现有active原子笔记，以证据ID关联功能条目。若提供reviews，逐条核验其sourceRevisionSHA256与当前完整记录摘要哈希一致，防止用旧建议覆盖新版本。相同证据ID的来源/偏移冲突会报错。输出已有时拒绝覆盖，不修改记忆库。

全部/部分/无证据关联仅用于发现漏项，不能证明摘要同义、语义完整或可直接合并。没有旧证据重叠的功能条目也不等于可直接新增的长期记忆。新旧摘要的修订应保留理由、当前采用版本和历史，确认状态与执行权限另行处理。


## 功能候选与原话联合检索

```bash
python3 scripts/search_products.py 关键词 --result product-明确采用的结果 --date 2026-11-12 --function actions
```

可重复传入`--result`查询不同日期请求，支持`--limit`和`--offset`。不自动混入历史版本：同一请求多修订或不同证据快照会拒绝，所有所选结果先校验工件哈希，部分结果会在sources中明确其状态。

返回`matchFields`区分`summary`（审阅摘要命中）和`evidenceQuote`（某条原话命中）；`matchedEvidenceIds`只列原话中实际含全部关键词的证据。摘要可以连接省略了主题词的后续说法，但命中摘要不能声称原话也说过该词。每条结果附完整匿名候选和引文，仍未确认主体、现场/媒体来源和历史任务当前状态。它是只读关键词回查，不是自动回答或语义检索，不改原文、不写记忆、不执行录音口令。

原文全文检索仍使用`search_recordings.py`；未被提炼的短句及外放原稿不会因候选检索而丢失。
