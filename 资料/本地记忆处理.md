# soundlog 本地记忆处理

当前实现将录音机器逐字稿组织成独立的本地记忆：Markdown 保存原子观察与关系，SQLite 提供可重建检索；模型提出 ADD / NONE / UPDATE / DELETE / UNRESOLVED，程序负责证据校验、去重、审核和可撤销写入。没有安装额外依赖。

记忆库默认在项目 `记忆库/`，已被 Git 忽略，与正式 Basic Memory 项目独立。本实现借鉴 Basic Memory 和 Mem0 的组织与更新方法，没有安装或调用 Mem0，没有声称已经与 Basic Memory 服务完成互操作验证。正文采用 `Observations`、`Relations`、permalink 和 wiki 链接。

## 开始使用

在项目根目录执行，Python 3.9 或更高版本（macOS/Linux）：

```bash
python3 scripts/memory.py prepare --date 2026-11-07
python3 scripts/memory.py export --date 2026-11-07
```

`prepare` 只读取现有运行产物，不读取音频、不重新识别。`export` 返回本地请求目录，里面有：

- `materials.json`：逐块材料，不含本机源路径和工件路径。
- `instructions.md`：模型任务、候选格式及来源约束。
- `result-template.json`：填写结果的外壳，必须保留 requestId 和 chunkId。
- `request.json`：供程序验证的本地快照，不需要分享。

只将前三个文件交给所选助手；这是全文文字材料，仍包含录音内容。生成结果保存在本机后导入：

```bash
python3 scripts/memory.py import --file /absolute/path/result.json
python3 scripts/memory.py search 录音 --date 2026-11-07
```

不需要在导出文件里设置凭据。未提供模型配置时，API 命令明确报错，导出导入仍可使用。程序不默认运行后台任务，也不自动接入录音导入流水线。

## 候选与结果协议

模型结果外壳：

```json
{
  "schemaVersion": 1,
  "requestId": "req-从模板复制",
  "model": "实际模型或处理者名称",
  "results": [{
    "chunkId": "chunk-从模板复制",
    "candidates": [{
      "type": "todo",
      "content": "联系供应方",
      "assertion": "explicit",
      "occurredAt": null,
      "subject": "我",
      "responsible": null,
      "entities": [],
      "dueText": "明天",
      "dueDate": null,
      "evidence": [{"id": "ev-从材料复制", "quote": "我明天联系供应方"}]
    }]
  }]
}
```

候选可选提供 `functionUses`，取 `journal`、`minutes`、`actions`、`learning` 中一项或多项。标签不改变候选ID；旧格式保持兼容，精确重复合并时保留用途并集。四类派生文稿的独立工作流见[四类功能提炼](四类功能提炼.md)，生成文稿不等于正式记忆同步。

候选类型为 `event`、`decision`、`todo`、`insight`、`preference_statement`、`person_mention`、`project_mention`。`assertion` 为 `explicit`、`suggestion`、`negated`、`reported`、`uncertain`；决策和待办只接受 explicit。其他类型仍保留陈述方式，不能把转述当本人事实。

引文必须是引用片段中逐字匹配的非空文字。主体、责任人和实体只能来自引文或片段的文件内匿名声音标签，未知用 null。`occurredAt` 非空时必须落在引用片段内；`date` 是证据所在自然日，不等于模型推断的事件日期。

首版保守处理期限：`dueText` 保存原话，`dueDate` 只接受原话内出现的明确 `YYYY-MM-DD`，不自动猜“下周五”等含糊日期。机器候选一律不自动成为已确认事实。校验能发现无效引证和字段越界，不能证明模型摘要在语义上完全忠实，仍需要试用核对。

缺失块和无效候选写入运行错误清单，其他有效内容可独立保存；部分成功的命令返回退出码1。空 candidates 表示该块确实处理过但无内容，不能用空列表冒充尚未处理的块。

## 语义比对与审核

普通导入先保存候选（UNRESOLVED），不让外部结果任意指定要改写的旧记忆。第二轮导出检索到的相似旧条目：

```bash
python3 scripts/memory.py export --date 2026-11-07 --resolve
```

这次模板中每个结果填写 `proposal`，而非 candidates：

```json
{"chunkId":"resolve-mem-...","proposal":{"action":"UPDATE","target":"mem-...","reason":"新证据明确更正了旧内容"}}
```

外壳及导入命令与首次相同。比对目标仅限本轮导出的旧条目；旧条目或候选变化后，过期结果被拒绝，需要重新导出。

- ADD：存未确认候选；同一证据、内容、日期、主体及期限的重复不再建条目。
- NONE：保留原条目并追加证据及提取来源，已经入库的重复候选标为 merged 并保留 mergedInto 关系和历史；不同日期、不同类型或不同主体不能自动合并。匿名主体还需同一文件内说话人或同一证据支持。
- UPDATE / DELETE：保存待审核变更，旧正文继续有效。
- UNRESOLVED：保留独立候选，可关联疑似冲突条目。

```bash
python3 scripts/memory.py review list
python3 scripts/memory.py review approve change-变更编号
python3 scripts/memory.py review reject change-变更编号
python3 scripts/memory.py confirm mem-记忆编号
python3 scripts/memory.py undo op-操作编号
```

`confirm` 表示用户确认一条文字候选，不登记或确认声纹身份。批准 UPDATE 后旧条目标为 superseded，新条目 confirmed；批准 DELETE 标为 revoked，不物理删除。审核会校验旧条目指纹。所有更改均保存前后快照；撤销拒绝覆盖后续修改或人工编辑，应先撤销后续操作。撤销已导入内容后保留处理回执，重复导入同一结果不会悄悄恢复被撤销内容。

## API 配置与自动处理

首版适配 OpenAI 兼容的聊天接口：配置 API 基地址（一般以 `/v1` 结尾），程序追加 `/chat/completions`。不使用供应商 SDK。实际提供方、模型、数据保留政策及费用由所选服务决定。

配置环境变量：

- `SOUNDLOG_MEMORY_API_BASE`：服务基地址。
- `SOUNDLOG_MEMORY_MODEL`：实际模型名。
- `SOUNDLOG_MEMORY_KEY_ENV`：保存凭据的环境变量名，默认 `SOUNDLOG_MEMORY_API_KEY`。

不要把密钥写进命令参数、项目文件或结果文件。命令支持 `--base-url`、`--model`、`--key-env`、`--timeout`；凭据只从环境读取。

```bash
python3 scripts/memory.py extract --date 2026-11-07
```

该命令会将指定日的全部机器文字按块发送给已配置服务，并发送与当前候选相关的少量旧记忆进行比对。原音频、声纹和本地源清单不会发送。请求不会跳转至其他服务；远程服务要求 HTTPS，本地回环模拟服务允许 HTTP。

分组采用90秒停顿规则，长场景及超长单句继续切块，必要时重叠一段并按证据引用去重；声学上下文最多附带20个按事件数排序的“源文件×标签”统计项，完整声学候选留证据包。每次网络或格式错误最多重试一次。成功块保留回执，重复运行复用；失败块下次重试，块内已保存候选也有幂等回执。API 结果使用与导入相同的候选校验及审核引擎。

`ModelAdapter` 是模型调用协议；`LocalModelAdapter` 仅为显式报未实现的接口，当前不接本地大模型。

## 本地结构与维护

- `证据/日期/指纹/`：不可变逐句快照与本地来源清单，含原始偏移、源哈希和工件哈希；保留 reportedPath，以来源文件名查找已移动到归档的音频。
- `笔记/原子记忆/`：有效正文，frontmatter 中 soundlog JSON 保存元数据，Observations 保存可编辑内容。
- `笔记/日记录/`、`笔记/实体/`：由原子正文重建的关系索引页，实体提及不代表真人确认。
- `审核/`：建议及审核状态。
- `运行/`：请求、结果、回执、错误和事务历史；这些是撤销和恢复所需证据，不应单独清空。
- `索引/`：可丢弃重建的 SQLite。

```bash
python3 scripts/memory.py reindex
python3 scripts/memory.py search --type todo --status candidate
python3 scripts/memory.py search --entity 项目名称 --include-inactive
```

检索默认排除 revoked / superseded / merged，支持日期、类型、实体、确认状态与 Unicode 规范化后的关键词。多个空格分开的关键词要求同时命中。不提供语义向量检索或生成式问答。

可以直接编辑原子笔记 Observations 中的一行内容，再重建索引；不要随意修改 soundlog 元数据、编号或证据字段。日记录和实体索引页会被重建。程序采用单写入锁、原子替换和写前事务记录；进程中断留下 pending 事务时，下次打开自动回滚，再重建派生索引。

全局 `--store` 与 `--runs` 参数放在子命令前，可指定隔离试验目录。笔记、证据、导出材料、索引与运行历史均含私人内容，默认库已忽略；自定义库目录应自行保持相同边界。

## Basic Memory V2 接入预览

在正式写入前，可从当前明确选中的六天产品结果生成独立预览：

```bash
python3 scripts/memory_v2_preview.py
python3 scripts/memory_v2_preview.py --verify 记忆库/运行/V2接入预览/preview-预览编号
```

命令先核对两个产品结果的全部工件哈希、每日场景原文快照哈希、5,074处候选引文和既有本地候选；再把建议写入内容生成到 `记忆库/运行/V2接入预览/preview-.../`。它不会写入正式 Basic Memory，也不会覆盖旧预览。目标命名空间是正式 Basic Memory 项目根下的 `soundlog/`，如果该目录已经存在就停止，要求先处理路径冲突。

`--verify` 只读检查已有预览的完整工件集合和 SHA-256，并逐篇验证 frontmatter、正文标题、候选仍处于未确认状态、主体/媒介仍未知、每条候选引文都能回到来源页锚点、每日索引链接都指向现存候选，以及各项数量与 manifest 一致；同时报告正式目标目录当前是否存在。文件或关系不符时返回非零错误。该命令不重新判定摘要语义质量。

正式写入器尚未放行；可先在专用隔离目录验证文件级写入链：

```bash
python3 scripts/memory_v2_sync.py apply-preview --preview 记忆库/运行/V2接入预览/preview-预览编号
python3 scripts/memory_v2_sync.py verify-readback --preview 记忆库/运行/V2接入预览/preview-预览编号
python3 scripts/memory_v2_sync.py revoke --operation-id 操作回执编号
```

同步器只允许写入项目忽略的 `记忆库/运行/V2隔离模拟/`，不接受正式 Basic Memory 路径；它先对整批路径做冲突预检，创建-only原子落盘，重复相同预览复用一致文件，失败回滚本轮写入；撤销前要求本轮创建的所有文件内容都未变化。它模拟的是Markdown文件写入/读回/撤销，不代表Basic Memory MCP已经建立正式图索引，也不能验证语义质量。

预览的目标结构：

- `soundlog/sources/index.md` 与 `sources/YYYY-MM-DD.md`：完整保留六天的11,833条机器转写原文、时间、匿名文件内说话人标签、来源文件名及哈希；覆盖清单单独保留42个音频源中41个有转写、1个无转写的缺口。不会复制音频或导入声学候选。
- `soundlog/candidates/YYYY-MM-DD/<fact-id>.md`：794条功能候选，保留功能用途、陈述性质、未知主体、未知媒介、原话时间/期限及逐句引文；全部仍为候选状态。
- `soundlog/daily/YYYY-MM-DD.md`：逐日原文与候选索引及用途计数，不额外生成摘要。
- `soundlog/confirmed/`：保留给以后经用户确认的记忆；本次预览不会在此目录创建内容。

现存本地旧库实际有138条记录：137条有效候选及1条已合并记录。预览将137条候选与新事实按相同原文证据做交叉索引；这是来源重叠，不是语义等价判断，不执行自动合并或覆盖。阅读预览中的 `legacy-crosswalk.json` 可查看映射，`manifest.json` 的SHA-256只证明预览文件未变，不证明摘要正确。

正式写入仍是单独步骤：先人工审核目录、交叉映射和全部候选内容；获得明确授权后再实现隔离写入、MCP/本地读回、幂等重试、冲突更正与撤销验证。此前24例回顾性审阅不等于计划要求的生成前标注/8例留出语义验收；本预览不能替代该质量门槛。录音识别质量仍需听音确认。

测试使用合成文字和本地 HTTP 模拟 API，不调用外部服务或识别模型。初期两条手工核对样例仅验证入库、回查和幂等。后续两天全量文字提炼已经完成，结果与核验见本机 `记忆库/运行/全量提炼/处理报告.md`；仍不能代表原始语音识别准确性验收。
