# 新版场景素材与全原文检索

实现日期：2026-11-13。生成器：`daily-evidence-v2.0`。只读取现有运行产物，不重新处理录音、不调用模型、不登记身份、不写入正式Basic Memory。

## 生成新版素材

在项目根目录运行：

```bash
python3 scripts/build_daily_scenes.py
```

默认读取 `产出/运行历史/`，将完整快照写入 `产出/大模型分析素材/每日场景-v2/snapshot-<指纹>/`。旧版 `每日场景/` 保留。`latest.json` 只指向没有警告的全量快照；命令结果的 `snapshot` 是本次阅读入口，目录内有 README.md。

可用 `--runs` 和 `--output-dir` 指定隔离输入输出；`--date YYYY-MM-DD` 可重复指定用于预览。部分日期预览不会替换全量默认入口。`--gap-seconds` 设置非负转写间隔，默认90秒，不意味着真实场景或无语音。

每个自然日保存：

- `YYYY-MM-DD_utterances.json`：全部长短机器原话、证据ID、源哈希、文件、偏移、钟表时间和文件范围匿名标签。
- `YYYY-MM-DD_acoustics.json`：全部声学候选、解释空值、原事件与窗口索引引用。原事件没有置信度时不伪造；窗口候选分数仍在来源NDJSON中。`unknown`表示没有达到分类阈值的类别，不是额外的原始声音类别。
- `YYYY-MM-DD_sources.json`：来源文件引用、产物路径/哈希、警告。
- `YYYY-MM-DD_scenes.json`：所有候选片段及逐句/声学证据引用，不按短句或字数丢弃。
- `YYYY-MM-DD_候选片段.md`：连续阅读入口与功能提炼要求。

快照 `receipt.json` 记录版本、实现文件哈希、输入指纹、文件哈希、条数、旧版计数比较、耗时及警告。先在临时目录完整生成再发布；重复生成校验后复用，不覆盖快照。异常返回码2；带警告的部分结果返回码1，不替换默认入口。进程并发写入被锁拒绝。

## 查全部原文

```bash
python3 scripts/search_recordings.py 轮胎 --date 2026-11-07
python3 scripts/search_recordings.py '机票 积分' --limit 20 --offset 0
```

关键词以空格分开时要求同时出现在同一条机器发言内；使用Unicode规范化及大小写折叠。支持日期、分页，以及 `--scenes <快照目录或其父目录>`。默认使用新版全量快照。结果返回原文、证据ID、源文件、偏移、时间和匿名候选；跨日同一证据在全库结果中只返回一次，同时列出涉及日期。

这是关键词检索，不是语义问答；它覆盖所有机器转写，不依赖137条候选是否已确认。没有匹配返回空列表；快照文件缺失/改变明确报错，不能伪装成无匹配。

## 解释与使用边界

- 展示标签如“文件名@源哈希前缀:S1”，JSON保留完整源哈希限定的标签。不同文件同号不合并；显示姓名和本人筛选尚未实现。
- 声音类别忠实保留，不把鲸类发声改成通风；无候选只说明未获得候选。
- 来源媒介、主体、事件发生时间和场景解释保持未知，后续理解要独立给出证据。不是所有发言发生的事情都在录音当时发生。
- 广播/外放自动识别尚未实现；新版避免默认归属，不声称已成功判断所有来源。
- 跨午夜发言与声音事件可在两天引用同一完整证据；切分不改原始边界，不重复制造事实。
- 每日素材尚不是已完成的日记、会议纪要、待办或学习笔记；这些是V1后续语义提炼任务。

## 批处理错误状态

`process-inbox.sh` 已对单文件素材失败、找不到产物、归档同名冲突和日素材失败返回失败状态。归档在同一文件系统内以硬链接创建目标、再移除待处理路径，不覆盖已有原件；无法跨文件系统归档时保留输入并报错。已有同名归档即使内容相同也先报冲突，不自动删除重复来源。

日素材生成失败发生在归档之后时，已归档原音和底层结果仍可用；修正原因后单独运行 `build_daily_scenes.py` 恢复，不必重新推理。单文件素材失败则来源仍在待处理箱，重试可复用底层处理结果。
