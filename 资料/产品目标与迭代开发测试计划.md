## 1. 产品总体目标

让普通录音笔采集的声音，在本机成为可回查、可整理、可问答、可持续更新的个人生活与工作记忆。日常使用目标是：导入录音后，能阅读当天记录、获取讨论纪要和知识笔记、查看待办与安排，并回答跨天问题；需要时由其他助手经授权读取相关背景。

成功不以提炼条数、音频处理成功率或字数覆盖率代替，应看用户能否完成这些任务：

1. 看懂录到的一天：发生了什么、讨论了什么、哪些只是回忆或计划。
2. 找回一段话：谁在什么录音中说了什么，原话和原音位置在哪里。
3. 跟踪事项：有哪些承诺、安排、条件，后来是否完成、取消或变更。
4. 沉淀知识与背景：学到什么、想过什么、作过什么选择及原因。
5. 延续跨天与跨助手上下文：读取有来源、状态和有效期的记忆，并能更正。

### 内容价值原则

能支持目标功能，或为它提供必要上下文的内容，就是高价值内容。生活小事、未定方案、反对意见、外部课程、他人讲话均可能高价值。不能仅因没有待办、不是本人讲话或内容很短而丢弃。

价值与可信度、主体归属、适用时间、确认状态和执行授权分开。未知来源可以进入匿名摘要和检索；生成本人事实、稳定画像、确切日程或外部执行指令时，才处理影响该功能的疑点。不是所有素材都要先由用户逐条确认。

原文完整保留；功能提炼不等于全部原文都要变为长期人物记忆。未提炼片段仍应可查；短期历史记录不自动成为长期偏好。

### 产品边界

- 本地离线是目标默认路径。底层音频分析已经本地实跑；高阶提炼目前依赖助手导出/导入或显式配置的API，本地功能草稿适配器处于未通过语义验收的实验阶段，不能称全链路自动离线已完成。
- 音频、机器原稿、候选、人工确认和推断各自保留；源音频与时间轴不改写。
- 当前主要处理录音结束后的批次；实时转写/同传、视觉抓拍、真实Vlog、PPT/板书融合、专有拾音硬件留后续独立评估。
- 自动删除原音、云端调用、下载安装、身份登记及向外部应用写入不由本计划自动授权；开发时遵守当前项目规则。

| 功能 | 用户可得到什么 | 验收重点 | 迭代 |

## 4. V1：可信素材与首批可用功能（下一版）

### A. 统一证据与修复场景生成

1. 优先复用现有 `scripts/soundlog_memory/evidence.py` 的源哈希、偏移、逐句ID和文件范围声音标签，避免场景层另建不一致的证据标准。
2. 全部转写与声音证据有独立结构化入口；主干片段和零星短句均可查。仅声音没有文字的时段也可查，不强行推断活动。
3. 匿名标签以源哈希和文件内编号限定；显示可用文件简称，但不能让不同文件S1混为同一人。
4. 声学分类保留原类别、置信度和原窗口/事件引用。中文名称忠实翻译；情境解释另列，无候选不填室内静默。
5. 90秒规则明确为转写片段间隔。跨文件讨论允许连续阅读，不能据此确认同一说话人。重叠区间按当前最大结束时间计算间隔，保留毫秒；跨日片段两天均可引用同一证据，不重复造事实。
6. 候选情境、来源媒介与事件发生时间分开。现场/媒体/未知判断允许未知，音乐标签或医院广播不能单独证明媒介或本人活动。
7. 替换内置提示词：按产品功能组织信息；禁止猜本人、填满日程、把外放当本人观点、把候选声类当现实事实。
8. 生成器具有版本、输入指纹和处理回执；改版写入独立输出位置并提供与旧版差异，验收后再切换默认入口，旧材料保留供回查。
9. 修复流水线状态：素材生成或归档失败必须明确报错并返回失败，不能因底层CLI成功而把后续环节全算成功；避免覆盖已有同名归档文件。

## 5. V1测试与验收计划

以下为待执行计划，数量和门槛为本次提出的首版工程验收目标，不是已达到的指标，也不是全部录音识别准确率。

### 5.1 自动化证据与故障测试

至少覆盖下列独立风险：

| 测试 | 通过条件 |
|---|---|
| 两文件都含S1 | 显示和结构化引用均不合并身份 |
| 跨文件连续讨论、区间重叠、毫秒边界 | 原始时间不变；片段间隔按覆盖末端计算；不丢字或造重复 |
| 跨午夜发言及声音事件 | 自然日两侧能查到原证据，源ID及引用一致 |
| 相同源存在多个运行快照 | 确定性选择有效版本，重复运行不增加副本 |
| 声音无文字、文字无声音候选 | 两类证据各自保留；不生造地点、静默或文字 |
| 动物声等可疑分类、多个声音候选 | 原分类及分数保留；解释与观测分开 |
| 医院叫号、疑似课程外放、未知来源 | 不自动归为本人就诊或本人观点，知识内容仍可提炼 |
| “不用买了”、建议、假设与相对日期 | 不变成无条件待办；不猜期限与完成状态 |
| 零星短句、否定词、MARK | 全量证据可查，关键语义不被长度过滤 |
| 无效引文、丢块、过期快照 | 明确失败或待复核，不冒充完成 |
| 写入中断、坏JSON、素材失败、归档冲突 | 原件不受损、错误可见、失败返回值正确 |
| 旧137条及协议升级、重复导入、撤销 | ID/历史可追溯，不重复、不静默覆盖确认状态 |

已有33项记忆测试继续通过；按修改范围增加上述实际行为回归用例。未修改Swift原生核心时不重复跑42份音频；修改原生代码后再执行相应Swift测试及必要的本机代表样本。

### 5.2 真实文字语义验收

- 从6天原文选择至少24个代表片段，覆盖生活日记、讨论纪要、待办/变更、外部学习四类，每类至少6个，允许额外加入模糊/无答案案例。
- 在生成前人工对照原文记录应保留的信息点、允许未知项、禁止归属及参考引文；留出其中8个作未参与提示词调整的验收片段。这里的人工是原文审阅，不等于录音持有人确认真实身份。
- 已标定功能信息点提炼召回率目标≥90%；生成陈述的证据支持率目标≥95%。另设硬门槛：验收集内未经依据认人、把媒体观点归本人、把否定变肯定、捏造原句/金额/期限均为0。
- 标注和评分按信息点计数，逐条列漏项及错误；总体分数过关也不能抵消上述严重错误。模糊来源正确输出未知计为正确，不以强行给答案提高覆盖。
- 没有真值的场景媒介判断标为未验证；不得将文字审核数字称为音频转写准确率。

可执行流程见[生成前语义验收流程](语义验收流程.md)，入口为 `scripts/semantic_gate.py`。准备阶段核验选择的证据没有在同一快照的既有产品结果中处理过；冻结阶段记录生成尚未开始、对四类24例逐点标注并隔离8例留出；评分阶段要求人工标注每条生成陈述的引文支持和严重错误，程序只核对引文/ID并计算指标。若现有结果已处理证据，准备器会拒绝，不把事后重评包装为预生成实验。

11月7—12日原文均已进入既有提炼结果，不能从这些材料回溯构造前瞻评测集。11月13日新录音已生成2,080条转写及135块产品请求，并已完成100条功能候选；已准备的24例/8例分组和agent标注冻结包中，标注与留出样本均已对当前agent可见，不能作为独立人工金标准或盲测。新包只用于流程演练；真正的发布门仍需隔离生成和独立人工逐项评审，尚无评分报告。

### 5.3 六天完整性与产品试用

- 按源证据ID核对输入输出集合：所有可用转写均可检索，无解释丢失0条；声音证据可回查。当前11,833条作为基线，去重/跨日规则导致数量变化必须给出明细，而非强凑原数。
- 随机加定向抽查至少30条输出引文，源、偏移、原话匹配率100%；自动校验覆盖全部引用。
- 设计20个有答案的关键词回查问题及5个无答案问题，答案证据事先对照原文标定；有答案问题目标至少18/20命中指定证据，无答案不捏造匹配。
- 实际用例包含：找轮胎讨论、比较出行备选、查看某天家庭片段、找课程概念、查任务是否有后续变化；若主体未确认应显示归属未知。
- 记录新处理与复用的不同耗时、运行资源和失败重试；不把复用量计入模型新处理吞吐。先形成基线，不预设“1秒回答”等未经验证承诺。
- 重复生成/导入一次，确认正文语义稳定、候选不增殖、确认与更正历史不丢失。

### 5.4 可选听音核验

用户此前暂缓听音，本版不将其作为所有功能上线的硬前置。文字证据测试通过只能证明忠于机器稿。若后续要评估真实转写、分人或媒介判断，另选安静对话、噪声、多人、外放、短句各2段共10段约30—60秒片段，获得人工真值后分别报告字符错误、漏词和分人错误；不能用10段外推整体准确率。本人声纹登记单独授权确认。
